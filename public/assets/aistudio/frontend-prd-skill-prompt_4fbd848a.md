# Skill Prompt สำหรับเขียน Frontend PRD

คัดลอกข้อความในกรอบด้านล่างไปใช้ใน Codex

```text
$skill-creator สร้าง Skill ชื่อ frontend-prd สำหรับเขียน Product Requirements Document ภาษาไทยจากแนวคิดเว็บแอป ให้ทีมออกแบบและทีม Frontend อ่านแล้วรู้ว่าต้องสร้างหน้าจออะไร ผู้ใช้ทำอะไรได้ และจะตรวจรับผลอย่างไร

ขอบเขตของ Skill
อธิบายเฉพาะสิ่งที่ผู้ใช้เห็นและโต้ตอบบนหน้าจอ ห้ามรวมข้อกำหนด Backend/Server, Database Schema, API Endpoint หรือรายละเอียดการพัฒนา Authentication หากมีหน้า Login ให้อธิบายเฉพาะช่องกรอก ปุ่ม สถานะ และปลายทางหลังเข้าใช้งาน

ให้ Skill จัดทำ PRD เป็น Markdown โดยมี 6 ส่วน

1. ภาพรวมผลิตภัณฑ์ — ชื่อ คำอธิบายหนึ่งประโยค ปัญหาที่ต้องแก้ และผู้ใช้เป้าหมาย
2. User Stories — อย่างน้อย 5 ข้อ ใช้รูปแบบ “ในฐานะ [ผู้ใช้] ฉันต้องการ [การกระทำ] เพื่อให้ [ประโยชน์]” และครอบคลุมทุกความสามารถหลักในโจทย์
3. หน้าจอและการนำทาง — สำหรับแต่ละหน้าจอ ระบุจุดเข้า ข้อมูลที่แสดง การกระทำหลัก และสิ่งที่เกิดขึ้นเมื่อผู้ใช้ทำเสร็จ ยกเลิก หรือย้อนกลับ
4. UI Components — ระบุองค์ประกอบของแต่ละหน้าจอ ชุดสี ตัวอักษร และการปรับ layout บน Desktop, Tablet และ Mobile หากมีการลากวาง ให้ระบุวิธีทำงานเดียวกันด้วยคีย์บอร์ดและการแตะ
5. User Journeys — เขียนขั้นตอนตั้งแต่เริ่มจนเห็นผล ระบุ client-side validation และสถานะ loading, empty, error, success ให้ชัดว่าข้อมูลที่ผู้ใช้กรอกจะเป็นอย่างไรเมื่อต้องลองใหม่
6. Mock Data และเกณฑ์ตรวจรับ — ให้ JSON ที่แปลงอ่านได้จริง มีทั้งข้อมูลปกติและกรณีขอบที่เกี่ยวกับโจทย์ ตามด้วยตัวอย่าง “เมื่อผู้ใช้ทำ… จะเห็น…” ที่ตรวจสอบกับข้อมูลชุดนั้นได้ หากผลขึ้นกับวันที่ ให้กำหนดวันที่ทดสอบ

รักษาชื่อสถานะ ปุ่ม และตัวเลขให้สอดคล้องกันทั้งเอกสาร หากต้องตัดสินใจกติกาที่โจทย์ไม่ได้กำหนดและมีผลต่อสิ่งที่ผู้ใช้เห็น ให้ระบุว่าเป็นสมมติฐานของรุ่นแรก

ใช้ TaskFlow เป็นตัวอย่างการเรียก Skill
“เขียน Frontend PRD สำหรับ TaskFlow แอปจัดการงานสำหรับทีม สมาชิกสร้างงานในโปรเจกต์ มอบหมายผู้รับผิดชอบ กำหนดความสำคัญและวันครบกำหนด ติดตามงานผ่าน Kanban Board และ List View ค้นหาและกรองตามสถานะ ผู้รับมอบหมาย หรือโปรเจกต์ และแสดงความคิดเห็นในงาน ใช้ UI เรียบ ทันสมัย เน้นสีน้ำเงินในแนว Trello/Asana”

สำหรับตัวอย่าง TaskFlow ให้มีเกณฑ์ตรวจรับที่พิสูจน์ว่าเมื่อกรองงานบน Board แล้วสลับเป็น List ผู้ใช้ยังเห็นงานชุดเดิม และเมื่อเปลี่ยนสถานะงาน ทั้งสองมุมมองแสดงสถานะล่าสุดตรงกัน
```
